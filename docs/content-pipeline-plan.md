# 内容数据方案：来源 → 契约 → 处理 → 检验

制定于 2026-08-29。适用于人物、事件、典章（制度/器物/名物）三类内容。
本方案不改动 `backend/sources/` 三个原始数据包，只重排它们的开采方式与派生内容的验收口径。

## 一、结论：不缺源，缺开采

| 内容层 | 现在用什么 | 已就位但未开采 | 真正缺的 | 判定 |
|---|---|---|---|---|
| 人物生平 | 维基条目全文（2163 篇） | 《明史》列传 222 卷（现仅 486 人挂原文块） | — | 够用，主次颠倒 |
| 生卒/亲属/任职 | CBDB 映射 557 人 | CBDB 为这 557 人就存着 **2678 条亲属记录，2439 条自带史料出处**；《明史》表 3 卷（宗室世系、宰辅、七卿、大臣年表）从未解析 | — | 够用且严重浪费 |
| 事件 | 维基条目（76 条，其中 25 条只有背景一栏） | **《明史》本纪 24 卷 = 322 条逐月编年记事**（实测计数），自带帝王+年+月 | 《明实录》（逐日粒度） | 主源用错 |
| 典章 | 维基条目（137 条，18 条脏数据） | 《明史》志 73 卷：职官 72、选举 70、食货 78、刑法 95、**舆服 65**、地理 40 | 《大明会典》《明集礼》（形制细节） | 来源不对口 |
| 地图 | 一张参考图 PNG | 志·地理有建置沿革文本，无坐标 | GeoJSON / 现代底图 | 完全缺源，另案 |

关键实测：手写卡片《王命旗牌》中的词组在《明史》332 卷里 **0 命中**（「旗牌」单独命中 10 卷）。
文字漂亮不等于有源——这是必须逐条登记出处的直接理由。

## 二、目标数据契约

三层结构，让「能不能给用户看」成为可计算的属性：

```
原文层  mingshi 卷N / person_wiki.full_text / CBDB 行
   ↓ 抽取 + 实体对齐，每段派生文字登记出处
派生层  综述文字 + 结构化字段（staging 库）
   ↓ 闸门不通过 → publishable=0
发布层  /v1/bootstrap 只吐 publishable=1
```

### 2.1 出处登记

`source` 表现状只有 1 行（`mingshi-editorial-v1`，状态「待卷次校核」），1453 人零出处记录。
`content_reference` 扩为：

| 列 | 含义 | 例 |
|---|---|---|
| `source_pkg` | `mingshi` / `wikipedia_zh` / `cbdb` | `mingshi` |
| `work` / `juan` | 书名与卷次 | `明史` / `卷065·舆服一` |
| `entry_key` | 可复核定位 | `太祖本纪三`；维基为条目名 + revision |
| `locator` | 段/句定位 | 原文起止偏移 |
| `relation` | `原文引用` / `据以改写` / `仅线索` | |

界面呈现（**按已定口径**）：不设「资料状态」栏、不做「史料来源」按钮，出处只以一行
「出《明史·太祖本纪三》」写在正文末尾。栏目仍是生平 / 家族 / 人物关系 / 相关事件。

### 2.2 分层验收（四个方面能不能实行的答案）

现状：生平 ≥300 字只有 1057/2200；家族 ≥80 字只有 291；有关系边的只有 108 人（4.9%）；
被事件引用的只有 64 人（2.9%）。CBDB 两端都在库内的可点击亲属边仅 44 条。

因此**不能要求人人四栏齐全**，改为两层口径：

- **精编层**（约 500 人：全部帝王 + 有《明史》传者 + 名臣名将）
  四栏齐全率 ≥90%；生平 400–1200 字四段式；每段带出处；关系边 ≥2 条
- **全量层**（其余约 1700 人）
  生平 ≥300 字且带出处；家族/关系/事件按实际有无，**整栏隐藏即为合格**

### 2.3 各类记录必填项

**人物**
- `category` ∈ 六类，DB 加 `CHECK` 约束；归类由三源投票（维基实体类型 + 明史列传类目 + 官职关键词）
- `reign` 必须是 17 年号之一或显式的「明前」「南明」等值，**禁止「明代」兜底**（现 1531/2200 = 69.6% 是兜底，导致年序排序全部沉底）
- 生平四段：早年 → 入仕/起事 → 主要事迹 → 终局与身后
- 与维基原文 30 字锚点重合率 <10%
- 生卒不可考一律写成 `？—1380` 规范形态（现 `years_of` 解析失败会静默跳过年龄校验）

**事件**
- 六栏齐全（背景/经过/相关人物/结果/影响/出处）；本纪有月的必须填月
- 相关人物须同时通过「名字出现于该条首段」+「年份落在生卒期内」，且存 `person.id` 引用
  （现 `participants` 是「、」拼接的姓名字符串，App 只能同名精确匹配，无法消歧）
- 出处 = 本纪卷次

**典章**
- 五要素：定名句 / 年代（`era` 必填，现 129/137 为空）/ 运作方式 / 一条具体史实例 / 出处
- 硬闸门：命中「可以指」「请见」「有以下…人」「(消歧义)」或描述 <60 字 → 不入库
  （现存 16 条 <30 字、18 条消歧义命中，含把韩国男演员写成「南明烈」入库）
- 制度/职官/舆服/刑法/选举/地理类必须出自《明史》诸志

## 三、处理管线

现状 25 个脚本无总入口、无幂等、无备份，重跑会冲掉人工内容。改为 staging 模式：

```
backend/scripts/pipeline/
  00_snapshot.py        导出文本快照 + git tag，任一步失败可回退
  10_extract_mingshi.py 本纪 322 条编年 → 事件骨架；志 73 卷 → 典章候选；
                        表 3 卷 → 宗室世系与在任年，用于校验 family 与 reign
  20_align.py           原文实体 ↔ person.id 对齐（名字 + 年号 + 生卒三重校验）
  30_classify.py        三源投票重跑分类；清除全部「明代」兜底值
  40_compose_life.py    生平改写：明史传为主干、CBDB 补仕历、维基仅补细节
                        人工校订改用显式标记列 manual_edited，不再靠字符串猜测
  50_purge.py           朝代闸门补下限（现只挡晚于 1644，故汉朝卫青、宋朝李纲漏入）
                        + 典章消歧义闸门 + 非明人物规则化识别
  60_verify.py          见第四节，任一断言失败退出码非 0
  70_publish.py         通过校验才 export 到 data/content/*.jsonl
```

三个硬约束：只在 `data/staging.sqlite3` 上跑；每步幂等可重放；人工内容受列标记保护。

现存保护逻辑不一致的证据：`complete_all_profiles.py` 以「family 非空」为人工，
`refine_life_family.py` 以「不含 4 个标记子串」为人工，`enrich_cbdb_local.py` 只列 3 个标记，
而其中 3 个标记在库中命中 0 次——结果 956/1249 条 family 仅因「非空」被当人工保护。

## 四、检验

### 4.1 自动闸门

| 断言 | 现状 | 目标 |
|---|---|---|
| publishable 记录的出处覆盖率 | 34%（747/2200） | 100% |
| 生平与维基锚点重合 ≥50% 的条数 | 500 | 0 |
| 事件六栏齐全率 | 51/76 | 100% |
| 事件 month/place/consequence 空缺 | 各 25 | 0 |
| 典章 era 非空率 | 8/137 | 100% |
| 典章残条与消歧义命中 | 16 + 18 | 0 |
| `reign` 为「明代」的人数 | 1531 | 0 |
| 分类抽检误归率（内廷最重 153/190） | 80% | <5% |
| 关系边经审计覆盖 | 61/91 | 100% |
| 库内非明人物 | ≥3（卫青、李纲、明玉珍） | 0 |

### 4.2 测试必须能失败

`test_content_service.py:119`、`:154` 用的分类名是废弃的 `皇帝/名臣/名将`，SQL 恒返回空 →
断言恒真；生卒校验中 813 人「生卒未详」被 `continue` 跳过，完全不在覆盖内。
每条规则必须配一个反例断言（故意塞入 `category='皇帝'`、`years='？—？'`、
`description='X可以指：'`，验证闸门确实拦截）。

`audit_data_accuracy.py:193` 会整体覆写 `docs/data-audit.md`，等于自己改自己的判卷——
审计脚本改为只输出数据，结论文字由人工撰写并入库。

### 4.3 人工抽核

每类随机 20 条，对照 `backend/sources/` 逐句核（卷次是否真有其事、年代换算、
是否把小说家言写成事实）。典章与南明人物全量人工过一遍。

### 4.4 界面回归

模拟器走四屏 + 跨屏跳转 + 详情，与基线截图做像素比对；三条内容断言路径：

1. 任意非帝王人物，关系栏每条必须含本人姓名（**已于 2026-08-29 修复并验证**：
   `PersonProfile.kt` 的 `shownRelations` 漏了本人过滤，导致吴贤妃（库内 0 条边）
   显示「同僚 傅友德·共事于1381年征云南」「同僚 高拱·共事于1571年封俺答为顺义王」；
   修复后吴贤妃关系栏整栏隐藏，马皇后只显示「配偶」朱元璋）
2. 25 个空壳事件之一展开不得出现空栏目
3. 典章页不得出现「可以指」字样
