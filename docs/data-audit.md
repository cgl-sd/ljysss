# 内容准确性规则

## 当前发布基线

当前资料库收录 2,158 名明朝及南明人物、18 个朝代、100 件精选事件、183 条人物—事件关联、22 个机构、22 条典章与 99 条人物关系。内容版本真相为 `backend/data/content/*.jsonl`；SQLite 仅为由文本构建的运行产物。

## 人物准入

- 人物须能与中文维基百科条目匹配，并以年代、身份与《明史》锚点交叉确认属于明朝或南明。
- 同名的清朝、现代或其他朝代人物，以及无法给出正式第二行称号者，不进入人物库。
- `display_name` 使用可靠本名；`title` 只使用正式封号、官职、爵位或谥号，不使用“明朝官员”“明朝将领”等泛称。
- 分类只允许帝王、内廷、宗藩、朝臣、将帅、文苑。内廷仅含后妃、宫人与宦官；储君归帝王；宗藩不含储君；文苑不收曾任高官者。

## 正文与来源

- 生平只保留叙事性经历，删除参考资料、影视绘画、评价影响、家族名录、空括号、乱码、孤立标点及无关外文。
- 家族、人物关系、相关事件分别入对应分栏；没有可靠材料的分栏整栏隐藏。
- 每段发布文字必须有 `content_reference` 登记，来源以中文维基百科与《明史》卷次为主，CBDB 用于辅助校订生卒、籍贯、科第和亲属关系。

## 自动校验

- `backend/tests/` 检查分类、分栏、正式称号、人物存在性、事件五分栏、起止年、受控分类、人物关联、关系与数据库索引。
- `backend/scripts/audit_data_accuracy.py` 默认只读，用于新增或改动关系边、事件参与人物时的生卒与全文出现判据校验；只有显式 `--apply` 才会修改 SQLite，并须随后导出 JSONL。
- 内容修改后执行 `backend/scripts/content_store.py import` 重建 SQLite；若直接编辑 SQLite，再执行 `export` 回写 JSONL 后提交。
