# 两京一十三省：详情页设计简报

## 任务边界

请为 Android 阅读端提出一套可复用的详情页视觉与交互方案，覆盖“机构”“典章”“事件”三种内容。此阶段只产出设计方案，不要求改动现有页面，也不要求生成最终素材。

应用是离线资料库，正文、人物、事件均来自随 APK 发布的 SQLite。设计不能依赖网络请求、悬浮广告或外部网页框架。

## 既有视觉语言

- 底色为暖米白宣纸色，正文用深墨色，强调与可点击项用朱红，细边框用浅铜金。
- 标题主要使用宋体／衬线感字体；卡片使用轻微切角、低对比边框，不采用高阴影或玻璃拟态。
- 顶部已有栏目题字和底部四项导航。详情页不显示“返回机构／返回典章”等文字提示，也不要画带边框的返回按钮；使用系统返回并恢复原页面位置。
- 当前详情页以一张首卡、多个正文分栏卡和关联人物组成。文字必须可长篇阅读，不能把段落压缩成摘要墙。

## 三类内容与正式数据

| 页面 | 固定信息 | 可选内容 |
| --- | --- | --- |
| 机构 | 名称、所属六类、存续时期、摘要、职掌／组织／运行／沿革、常见仕途导览 | 代表人物、图片、来源 |
| 典章 | 名称、制度／器物／宫陵三类、时代、摘要、释义／形制／使用／历史脉络 | 相关人物、图片、来源 |
| 事件 | 名称、年份／月份／地点、背景／经过／结果／影响 | 横向排列、可点击的相关人物 |

事件保持独立阅读，不画为关系图节点；机构与典章也不应为了导航而强行建立交叉关联表。

## 希望设计方交付

1. 一套共用的详情页骨架，并给出机构、典章、事件各一张完整页面稿。
2. 首卡、正文分栏、横向关联标签、可选导览图、图片区域和长文排版的尺寸／层级说明。
3. 适配 360–430dp 宽度全面屏；首屏可迅速读出条目身份，长文自然向下滚动。
4. 为图片留出“来源图片”与“专题示意图”两种状态：前者要有小型来源标记区域，后者不得伪装成史实照片或文物实拍。
5. 不要设计固定的底部弹窗；事件、人物和其他详情都应是完整阅读页，返回恢复来源页的位置。

## 不应出现

- 审核完成、审核时间、离线包版本等编辑过程信息。
- 把机构再复制成典章，或把事件作为关系图中心节点。
- 未经授权的图片、无来源的“历史实拍”暗示或水印。
